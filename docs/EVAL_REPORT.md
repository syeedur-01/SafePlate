# Vision evaluation report

**Status: no recognition evaluation has been run yet.** No real provider
(Gemini or otherwise) has been scored against real images, so there is no
recognition claim in either direction.

## Benchmark state (2026-11-18)

- Dataset: BD-Food33 v1 (CC0 1.0), downloaded and SHA-256-verified; licence
  audit in `docs/EVAL_DATASETS.md`.
- Manifest: `eval/bd-food33.manifest.json` — 1,211 images across 33 dataset
  labels; 17 exact-byte duplicates marked `unused`; deterministic ~80/20
  dev/holdout split; 0 images mapped to the SafePlate catalogue so far.
- Excluded from the manifest: 25 files in formats the API does not accept
  (AVIF) and 2 files without a usable extension.
- Label map: `eval/bd-food33.label-map.json` — 8 clear matches proposed
  (Alu Vorta→aloo-bhorta, Bakorkhani→dhakaiya-bakarkhani, Chicken Roast→
  bangladeshi-chicken-roast, Fuchka→fuchka, Morog Polao→morog-polao,
  Peyaju→piyaju, Roshmalai→rasmalai, Shorshe Ilish→shorshe-ilish), all
  **pending human approval**; every other label is unmapped (proposed null
  with a reason). Unmapped labels are never scored.
- Harness: validated end-to-end offline with the deterministic mock provider
  on synthetic fixtures (`--mode local`); proven against the real manifest
  paths with `EVAL_PROVIDER=mock --max-calls 10`.

## What a real run will need

1. Human approval of the proposed label mappings (proposals are not approvals).
2. A real provider run — `EVAL_PROVIDER=gemini` spends paid API calls and is
   approval-gated; it is never run in CI.
3. A fresh `docs/EVAL_REPORT.md` generated by `pnpm --filter @sp/tools eval-run`
   recording provider, model, date and full metrics with support counts.

## Limitations

- Near-duplicate detection is exact-byte only; visually similar photos across
  categories still need manual review before split metrics are trusted.
- Label-OCR and spoilage-sign tasks have no real labelled data yet.
- The mock provider measures the harness, never recognition quality.
